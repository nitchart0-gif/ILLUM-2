# ILLYUM — Acceptance Tests & Definition of Done

Use these tests during implementation. Add implementation-specific tests only when they do not weaken or replace these requirements.

## A. Project and source
- A1: User can create, open, rename, and revisit a project.
- A2: Projects do not show each other's source or generated content.
- A3: Pasted story source is saved and visible after refresh/reopen.
- A4: Unsupported or inaccessible URL/file source is clearly reported; app does not claim extraction succeeded.
- A5: Navigation state persistence: Current view, active project ID, and active tab persist across user interactions and browser reloads via client storage.
- A6: Source Story Analysis pre-stage extracts characters, facts, chronology, locations/dates, developments, narrative arc, and flags missing details; reviewable in UI prior to script approval.
- A7: Skill 0 dedicated AnalysisRecord structure: `id`, `version`, `sourceVersion`, `sourceFingerprint`, `analysis`, `status` (`Needs Review`, `Approved`, `Stale`), timestamps, `modelUsed`.
- A8: Saving an edited analysis resets status to `Needs Review` and clears `approvedAt` (re-approval mandatory).
- A9: Source story modification invalidates existing analysis, marking it `Stale`; approval is rejected if source fingerprint does not match current source.
- A10: Analysis regeneration preserves older versions in `analysisVersions` array and increments version number without affecting existing scripts or story data.
- A11: Skill 0 dedicated UI tab appears in exact workspace order (Tab 2: Source Story, Skill 0 — Source Analysis, Skill 1 — Script, Skill 2 — Video Prompts, Skill 3 — Thumbnail Prompts, Skill 4 — SEO).
- A12: Skill 0 displays all 7 core analytical dimensions accurately without data fabrication; previous versions are viewable in immutable read-only snapshot mode.
- A13: Mandatory Approval Gate: Skill 1 script generation is blocked when currentAnalysis is missing, in `Needs Review`, or `Stale`.
- A14: Analysis Handover: Skill 1 receives the complete approved `AnalysisRecord` data; editing analysis clears approval; modifying source invalidates analysis to `Stale` while strictly preserving existing script versions.

## B. Skill 1
- B1: User selects Hindi or English during project creation (single source of truth). Hindi generates pure Devanagari (no mixed English sentences); English generates natural English with zero Devanagari. Language consistency is validated before saving.
- B2: Duration system adheres strictly to the 8-second formula:
  - 9:16: 3 Parts = 24s, 4 Parts = 32s, 5 Parts = 40s, 6 Parts = 48s. Formula: `Parts × 8s`.
  - 16:9: Numeric input in minutes (&ge; 3 minutes, reject < 3 min). Formula: `Total Seconds = Minutes × 60`, `Parts = Ceiling(Total Seconds ÷ 8)`.
- B3: Generated parts match the exact calculated count (e.g. 23 parts for 3m, 30 parts for 4m).
- B4: No individual part exceeds 8 seconds.
- B5: First part is Hook; middle parts are Story; final part is Ending.
- B6: Output includes part number, part type, voiceover, estimated duration (&le;8s).
- B7: Output strictly preserves source facts and chronology; zero hallucinated events/characters. Ambiguities flagged clearly.
- B8: User can edit, save, and approve a script. Edits are validated for language consistency.
- B9: A new generation preserves prior approved versions.

## C. Skill 2
- C1: Skill 2 is blocked unless an approved Skill 1 script exists.
- C2: Each script part has one video prompt.
- C3: Each prompt states duration, ratio, and resolution explicitly.
- C4: Prompts include all required visual, camera, lighting, action, character, environment, and continuity fields.
- C5: Exact approved voiceover is included and not rewritten.
- C6: Voice and music identity remain consistent across parts.
- C7: Text prompts only; no storyboard images are generated by this skill.
- C8: Skill 2 does not directly use the original story source.

## D. Skill 3
- D1: Skill 3 is blocked unless an approved Skill 1 script exists.
- D2: Exactly two options are produced.
- D3: A and B are genuinely different concepts, not simple color variations.
- D4: Strongest visual moment is selected from the whole script.
- D5: Ratio is explicit and matches selected output.
- D6: Prompts include mobile readability, hierarchy, text recommendation, quality constraints.
- D7: Text prompts only; no image is generated by this skill.
- D8: Skill 3 does not directly use original source story.

## E. Skill 4
- E1: Skill 4 requires both original source story and approved script.
- E2: Source and script are analyzed separately and together.
- E3: YouTube SEO and Instagram SEO are separate tabs/records.
- E4: YouTube title exactly matches first hook text.
- E5: YouTube description omits original article title, author, website, and link.
- E6: YouTube tags include all required groups and are comma-separated.
- E7: Instagram caption, keywords, hashtags, disclosure are present.
- E8: Live keyword claims are evidence-based; no fabricated metrics/trends.
- E9: No ranking/virality guarantee.

## F. Dependency, data and operations
- F1: Downstream skills are blocked when required script is unapproved.
- F2: Changing the approved script marks older dependent results Stale.
- F3: Output records identify source/script versions used.
- F4: Generation failures preserve user input and show retry guidance.
- F5: Progress/status matches actual execution and saved records.
- F6: User can copy outputs and export where supported.
- F7: App remains usable after refresh/reopen with selected persistence approach.
- F8: Secrets are not exposed in client code or UI.
- F9: Tracker and phase audit are updated at every phase boundary.

## G. Model discovery and free-tier fallback (FR-07)
- G1: Dynamic discovery retrieves available AI models from the configured provider.
- G2: Models are clearly categorized into Verified Free, Paid/Pro, and Unverified; unverified models are excluded from automatic fallback.
- G3: User can designate a primary free model and prioritize the fallback queue.
- G4: Rate limits (429) or temporary outages trigger automatic fallback to the next verified free model in the queue.
- G5: System never falls back to a paid or unverified model without explicit user confirmation.
- G6: Output record and UI explicitly report the actual model used and indicate whether fallback occurred.
- G7: Temporary 429 rate limits do not permanently disable a model; model returns to Available after cooldown.
- G8: API keys and credentials are handled strictly on the backend and never exposed in client code or network payloads.

## Final completion gate
All applicable tests pass, no critical requirement is missing, known limitations are documented, the user has reviewed the app, and the final phase is explicitly accepted.
